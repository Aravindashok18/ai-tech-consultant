# EVALS: what is measured, what is not

Everything below was run offline on this machine with no Claude API key. Numbers are copied from the scripts' output; nothing here is estimated. **The live-model parts (the ones that matter most for answer quality) are not measured yet.**

## Measured

### Task 1: retrieval on the full index (`task1-knowledge-brain/evals/run_retrieval.py`)
Index: 1,536 help-center articles, 11,853 chunks (hybrid BM25 + local `bge-small` vectors, rank-fused).

| Metric | Result |
|---|---|
| In-domain questions | 27 |
| Right article in top 1 / top 3 / top 6 | **85.2%** / **100%** / **100%** |
| Search latency (median / p95) | 14 ms / 18 ms |
| Best-hit cosine, in-domain (min / median) | 0.72 / 0.82 |
| Best-hit cosine, 6 off-topic questions (max) | **0.65** |
| Off-topic questions stopped by the cosine gate (0.5) | **0 of 6** |

How to read it:
- Retrieval finds the right article reliably when the question is about a real topic.
- **The cosine gate at 0.5 stops nothing.** On this set a gate near 0.68 would separate the two groups (0.65 off-topic max vs 0.72 in-domain min), but 6 off-topic questions is too few to change the default. For now "I don't know" depends on Claude's `can_answer` flag, which is unmeasured.

### Task 2: email classification, offline keyword fallback (`task2-inbox-agent/evals/classify_eval.py`)
**78% (39 of 50)** on the 50 seed emails. Confusions: `new_project→how_to` ×3, `other→how_to` ×2, and six single mistakes. This measures the crude fallback only. It says nothing about the Haiku classifier that would run in production.

### Unit tests
26 offline tests pass (Task 1: 8, Task 2: 10, Task 3: 8). They cover the parser (including the real help-center breadcrumb), sitemap handling, crawl add/update/remove, chunking, the approval gate (409 until approved), extra-work pricing, and the KB-down risk note.

## Caveats on the numbers above
- The 27 questions and the expected keywords were written by me with the answer article in view, so they are easier than real customer wording. Treat 85%/100% as an upper-ish bound, not a benchmark.
- "Hit" means an expected keyword appears in the title or text of a returned chunk, which is loose.
- The 50 seed emails and their labels were generated by the author (`emails/make_seed.py`).
- One run each; no repeats, no confidence intervals.
- The local database was crawled before a parser fix, so 797 of its 1,536 articles have an empty category. The fix has a regression test; a fresh crawl (the database is not in git) gets categories.

## Reproduce
```bash
cd task1-knowledge-brain && .venv/bin/python evals/run_retrieval.py      # needs data/brain.db (run the crawl first)
cd task2-inbox-agent     && .venv/bin/python evals/classify_eval.py      # offline unless ANTHROPIC_API_KEY is set
cd <each task>           && .venv/bin/python -m pytest -q
```
