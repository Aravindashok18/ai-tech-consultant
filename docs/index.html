This is a project overview, not the running app. This page is static. Nothing here answers questions, reads email or builds proposals. The three services run on your own machine (ports 8000, 8001, 8002); see how to run them.

AI Tech Consultant

One system for a software or service business: it knows the product, answers the inbox, and turns client meetings into a scope of work, an estimate and a proposal. Built as a four-day capstone for Business Labs.

Source code on GitHub DESIGN.md README.md

Why this exists

Code is now cheap. A website change that cost a small business about $2,000 two years ago costs about $200 today, so a tech company has to do 10 to 20 times more projects to pay the same salaries. The slow part is no longer coding. It is everything around it:

  • knowing the product inside out,
  • answering every customer email quickly and correctly,
  • and turning a long client call into work a developer can estimate.

Each task removes one of those bottlenecks. A wrong answer is worse than a slow one, so every part can say "I don't know" and hand over to a person.

How the three tasks connect

The three tasks

Task 1 · Python (FastAPI) · port 8000

Knowledge Brain

Memory and chatbot for the Brilliant Directories help center, kept in step with it.

  • Polite first read: one shared limit of 1 request per second plus jitter, robots.txt respected, backs off on 429/5xx. Every URL sits in a queue table, so a stopped crawl resumes where it left off.
  • Screenshots count: each image is captioned once, cached by image hash, and stored as a searchable chunk tied to its article.
  • Daily freshness: compares sitemap lastmod with memory, fetches only new or changed pages, deletes removed ones, and refuses to delete more than 25% in one run (that would mean a broken sitemap).
  • Answers with sources: BM25 plus local bge-small vectors, then a cited answer. When the sources don't contain the answer, it opens a task for a human expert, and the expert's reply is stored as a page that ranks slightly higher next time.
  • API: POST /v1/ask, /v1/search, GET /v1/articles, /v1/tasks, POST /v1/tasks/{id}/answer, /v1/feedback, /v1/admin/sync, GET /v1/stats.
Status: offline tests and a live crawl have run. Claude image captions and generated answers have not been run yet.
Task 2 · Python (FastAPI) · port 8001

Inbox Agent

Reads each customer email, gets facts from Task 1, drafts a reply, and learns from what the human does with it.

  • Flow: classify (12 kinds, urgency, risk flags) → ask Task 1 → draft in a JSON schema → human sends, edits, or writes their own.
  • What it learns: each edit becomes up to 2 short rules (for example "open with the answer") that go into the next prompt. Every rule can be undone in the UI.
  • Autopilot is earned: a kind of email may auto-send after 20 drafts in a row sent unchanged (text similarity ≥ 0.97), and only with confidence ≥ 0.8, no risk flags and a verified answer. Refund, cancellation, complaint, legal, billing and quote never auto-send.
  • Autopilot is revocable: 10% of auto-sent mail is spot-checked. One "wrong" verdict, or 3 edits in the last 10 human-handled mails of that kind, switches it off and restarts the streak.
  • Safety: email text is treated as data; prompt-injection phrases force human review.
Status: 50 sample emails written by the author. The only measured result is the offline keyword fallback: 78% correct on those 50 (no model involved, so not a Claude result). Claude classification and drafting have not been run yet. Sending writes to an outbox table; there is no real mailbox.
Task 3 · Python (FastAPI) · port 8002

Meeting to Scope of Work

Turns messy client transcripts into a scope, an hours estimate and a client-ready proposal draft.

  • Agents with one job each: extractor, settings checker (calls Task 1), estimator, clarifier, senior reviewer, reconciler, proposal writer. They pass JSON with stable ids (R1…, T1…).
  • Setting before custom code: each requirement is checked against the help center. If an existing setting does the job, the proposal shows the article and the hours saved.
  • Long transcripts: split on speaker turns into windows of about 6,000 characters with 2 turns of overlap, read in parallel, near-duplicates merged.
  • Meeting 2 updates, not restarts: each item is marked same, changed, dropped or new. New items become priced change requests, labelled as extra.
  • Money is code, not model: prices, totals, day counts and the 15% project-management margin are computed deterministically. The model supplies hours and prose only.
  • Human gate: versions start as drafts; the export endpoint returns 409 until a named person approves.
Status: offline tests have run. The Claude agents have not been run yet, and the offline fallback uses flat placeholder hours that must not be shown to a client. The three sample transcripts are scripted by the author, not recorded meetings.

Decisions and trade-offs

ChoiceWhy
SQLite with full-text and vector blobs instead of a vector databaseAbout 1,500 articles fit in memory. One file is easy to run and back up.
Local embeddingsNo per-query cost, and nothing leaves the machine.
All three tasks in PythonThe brief allows Python for Task 2, and it avoids mixing languages.
Haiku for high-volume steps, Sonnet for answers, drafts and estimatesThis is a hypothesis. The model-comparison evals that would prove it have not been run.
Dropped: real Gmail/SMTP, vector database or knowledge graph, voice recording of meetingsOAuth setup is out of scope; the data is too small to need the others; transcripts are pasted as text.

Where it is weak

  • The "I don't know" decision depends on the model. The vector-similarity gate is weak: off-topic questions still scored about 0.58 in a 30-page sample.
  • "Unchanged draft" is judged by character similarity, so a short edit that flips the meaning ("can" to "cannot") could look unchanged.
  • The Claude-powered paths in all three tasks have not been run, so quality, cost and speed for them are not measured. There are no model-comparison results yet.
  • Approval in Task 3 is a typed name, not a login, and the APIs have no user authentication.

Run it yourself

Needs Python 3.12 and an Anthropic API key. Without a key, Task 1 gives extractive answers and no image captions, and Tasks 2 and 3 use crude offline fallbacks.

git clone https://github.com/Aravindashok18/ai-tech-consultant.git
cd ai-tech-consultant
cp task1-knowledge-brain/.env.example task1-knowledge-brain/.env   # add ANTHROPIC_API_KEY
./run_all.sh

Then open localhost:8000 (chat and expert queue), localhost:8001 (inbox) and localhost:8002 (scope). API docs are at /docs on each port. Tests are offline: run pytest inside each task folder.
